# Архитектура broskiplay.ru

Памятка для последующих задач. Проверена по рабочей папке и коду 19 ноября 2026 года.
Все пути ниже — от корня репозитория, если явно не указано иное.
Правила владельца находятся в `../AGENTS.md`; эта памятка их дополняет.
При изменении сборки, структуры или источников данных обновлять соответствующий раздел.
Числа и список игр описывают состояние на дату проверки.

## 1. Общая схема

Сайт статический, публикуется на GitHub Pages, домен указан в `CNAME`.
Серверного приложения Next.js на хостинге нет: `web/next.config.ts` задаёт
`output: "export"`, `trailingSlash: true`, неоптимизированные изображения.

Это гибрид трёх частей:

1. **Next.js / React / TypeScript** создаёт главную, общий каркас, страницы карт,
   локаций и оболочки отдельных страниц. Tailwind v4 и компоненты shadcn/ui
   используются без сброса preflight.
2. **Обычный браузерный JavaScript** управляет картами, метками, прогрессом,
   фильтрами, входом и интерактивностью базы. Переноса движка карт в React нет.
3. **Python-генераторы** создают категории карт и базу данных. Сборщик Node.js
   вставляет их страницы в каркас, заранее экспортированный Next.

```text
js/script.js ── локальный prerender_home.py ── web/data/home-games.json
                                                       │
исходные HTML карт и отдельных страниц ────────────────┤
                                                       ▼
                                            Next build → web/out/

данные карт + категории ── category_pages.py → <игра>-map/c/
data/db/<игра>/*.json ───── db_pages.py ──────→ db/

файлы сайта + web/out/ + страницы Python
                  │
                  ▼
       web/scripts/assemble.mjs → _site/ → GitHub Pages
```

`npm run build --prefix web` также запускает `install-home.mjs`: копирует
главную из `web/out/index.html` в корень и заменяет корневой `_next/`.
Для проверки итогового сайта нужен `_site/`: исходные карты в корне показываются
без нового общего каркаса.

## 2. Где исходники, а где результат

| Путь | Назначение и место правки |
| --- | --- |
| `web/app/`, `web/components/`, `web/lib/` | Исходники Next: страницы, каркас, чтение и преобразование данных |
| `web/data/home-games.json` | Входные карточки главной для Next; локальный генератор извлекает их из `js/script.js` |
| `index.html` | Собранная главная; руками не редактировать |
| `<игра>-map/index.html` | **Исходник** страницы карты: DOM, подключения CSS/JS, SEO; его читает Next |
| `<игра>-map/js/`, `css/`, `data/` | Код и данные конкретной игры |
| `<игра>-map/<локация>/index.html` | Сгенерированные страницы локаций; не править вручную |
| `<игра>-map/c/` | Категории, результат Python; не править вручную |
| `data/db/<игра>/` | Входные JSON базы данных |
| `db/` | Сгенерированная база, включая HTML и индексы; не править вручную |
| `updates/`, `cabinet/`, `fixes/`, `reports/`, `design/` | Исходные HTML отдельных страниц; Next вставляет их содержимое в каркас |
| `privacy.html`, `404.html` | Исходные отдельные страницы с сохранением прежних адресов в итоговом сайте |
| `web/out/`, `web/.next/`, `_next/`, `_site/` | Результаты сборки / служебные файлы; не место для исправлений |
| `tools/`, большая часть `scripts/`, игровые `tools/` | Локальные инструменты; наличие на диске не означает наличие в git или CI |

`web/` исключена из копирования в `_site/`, поэтому эта памятка не становится
страницей сайта. Новую документацию удобно хранить здесь: корневые файлы
`assemble.mjs` по умолчанию копирует, кроме явно исключённых.

## 3. Next: страницы и общий каркас

В `web/app/` несколько групп маршрутов со своими layout. Скобки в имени группы
в URL не попадают.

| Группа | Итоговые адреса | Как получается содержимое |
| --- | --- | --- |
| `(home)` | `/` | React-компоненты главной + JSON |
| `(map)/[game]` | `/<игра>-map/` | Разбор исходного HTML игры через `web/lib/maps.ts` |
| `(loc)/[game]/[map]` | `/<игра>-map/<локация>/` | Та же карта с собственными метаданными и `<base href="../">` |
| `(page)` | `/updates/`, `/cabinet/`, `/fixes/`, `/reports/`, `/design/`, `/privacy.html`, `/404.html` | Разбор исходных HTML через `web/lib/pages.ts` |
| `(wrap)/wrap/[kind]` | Только промежуточные шаблоны | Каркасы `db`, `db-<игра>`, `c-<игра>-map`; не публикуются как страницы |

Основные файлы:

- `web/components/shell/`: `topbar.tsx` — шапка, `rail.tsx` — навигация,
  `footer.tsx` — подвал, `game-search.tsx` — поиск игр, `icons.tsx` — общие иконки.
- `web/components/map/map-shell.tsx` — HTML-документ и каркас карты (`.bx-map`).
- `web/components/page/page-shell.tsx` — каркас отдельных страниц.
- `web/components/shell/raw-head.tsx` — перенос тегов исходного `<head>` в React.
- `web/components/shell/legacy-scripts.tsx` — подключение старых скриптов
  **после гидратации**, в исходном порядке. Это важно: эти скрипты меняют DOM.
- `web/lib/maps.ts` — обнаружение папок `*-map`, извлечение списка локаций
  из игрового JS, разбор HTML, преобразование относительных URL, SEO локаций,
  ссылки на базу игры. Старое меню `mtb` и `map-topbar.js` при переносе убираются.
- `web/lib/pages.ts` — реестр отдельных страниц и разбор их HTML;
  убирает старый `topbar`, переносит файловые и встроенные скрипты тела.
- `web/scripts/assemble.mjs` — копирование файлов в `_site/`, наложение экспорта
  Next, перенос `privacy/index.html` и `page-404/index.html` на прежние адреса,
  оборачивание базы и категорий.

У базы и категорий скрипты Next из шаблонов удаляются: там нет гидратации.
Поиск шапки работает через `js/shell-lite.js`, Google-вход — через
`js/firebase-lazy.js` и `js/auth-lite.js`.

## 4. Главная

Меню выбора карты позиционируется абсолютно поверх соседних карточек в сетке и списке
на всех ширинах; высота ряда при раскрытии не меняется. Длинное меню прокручивается,
клик вне карточки и Escape закрывают его в обоих видах.

- `web/app/(home)/page.tsx` — порядок блоков и список подключаемых скриптов.
- `web/app/(home)/layout.tsx` — метаданные, JSON-LD, CSS; `data-theme="dark"` на `<html>`.
- `web/components/home/` — hero (заголовок, кнопки; справа `hero-art.tsx` — иллюстрации всех игр
  `<игра>-map/hero-art{,-960,-640}.webp` (WebP q95), сами сменяются раз в 7 с и стрелками ‹ ›, пауза при наведении/фокусе,
  без смены при reduced-motion; первая игра — `FIRST` в `hero.tsx`), «Продолжить» сразу после hero
  (разметку строит `renderRecent` в `js/script.js`: горизонтальные карточки: на ПК 2 в ряд, остальные до 6 — по «Показать ещё» `#recent-more`; на телефоне по одной, до 3, превью 38%; обложки карточек у всех игр — `<папка>/logo-card{,-720}.webp` 1080/720 px WebP q95, логотипных баннеров больше нет; на телефоне в сетке число меток в списке карт стоит под названием, меню «Ещё» прижато к правому краю ряда фильтров), категории,
  библиотека игр, финальный блок и экран загрузки.
- `web/components/home/home-client.tsx` — мобильный
  поиск, горячие клавиши, раскрытие карточек, диалог «О проекте», запуск PWA.
- `web/lib/data.ts` — чтение карточек, `data/changelog.json`, `data/goal.json`.
- `web/lib/home.ts` — жанры, категории, подписи карт/меток и ссылки карточек.
- `js/script.js` — конфигурации `*MapConfigs`, исходное описание карточек,
  `GAME_FRESH`, поиск, прогресс, авторизация; публикует `window.bpProgress`.
- `js/home-lib.js` — функции библиотеки игр, включая меню прогресса и избранное
  (звёздочка на карточке, избранные игры первыми; пункта «Избранное» в навигации нет),
  панель `.lib-bar`: фильтры «Все/Новые/С прогрессом» + «Ещё» (Недавние/С базой/Скоро)
  и отдельное меню «Сортировка»; выбор в `bp_home_filter` / `bp_home_order`.
- `scripts/prerender_home.py` — локально пересоздаёт `web/data/home-games.json`
  из отрисованных карточек `js/script.js`; требует Chrome. В CI не запускается.

Текущая главная подключает `ui-feedback.js`, `js/script.js`, `js/home-lib.js`.
Стили — `fonts/fonts.css`, `css/spatial.css`, `css/shell.css`, `css/home-neo.css`,
`css/ui-system.css` и последним `css/home-v3.css` (hero, панель каталога, карточки,
радиусы главной: элементы управления 8 px, карточки и панели 16 px) плюс собранные стили Next. `css/home.min.css`, `css/home-dash.css`,
`css/style.css`, `css/vision.css`, `js/home-dash.js`, `js/home-fx.js`,
`js/vision.js` сохранены в папке, но **не являются текущим набором подключений
главной**. Перед правкой всегда проверять реальное подключение в layout/page.

| `silver-palace-map/` | Silver Palace | 1 | `js/gate.js` и временная блокировка категорий в генераторе |

Обычная игра содержит `index.html`, `js/app.js`, `js/categories.js`,
`css/style.css`, `data/*markers.json`, `data/progress-index.json`, изображения
карточек/логотипов. Исключения указаны выше. Большие тайлы обычно находятся
во внешних репозиториях `<игра>-assets`, а не в этой рабочей папке.

`app.js` игры связывает конфигурацию тайлов, координаты, состояние, фильтры,
поиск, попапы, облако, экспорт/импорт и свои метки. Набор полей JSON различается:
помимо `markers` встречаются `regions`, `labels`, `texts`, `xlinks`, `zones`.
Не навязывать всем играм схему одной карты.

Списки карт дублируются между `app.js`/`maps.js`, `js/script.js` и данными
карточек. При добавлении карты проверять всю цепочку. `web/lib/maps.ts`
извлекает JS-блоки по конкретным объявлениям (`ASSETS_ROOT`, `MAPS`, `MAP_ORDER`):
их рефакторинг может сломать статическую генерацию адресов локаций.

## 6. Общий движок карт

| Файл | Ответственность |
| --- | --- |
| `vendor/maplibre/` | Локальная библиотека MapLibre GL |
| `js/bp-map.js`, `css/bp-map.css` | WebGL-карта, тайлы, метки; совместимый с прежним Leaflet интерфейс |
| `js/map-core.js` | Общие операции состояния, найденных меток, облачной записи, видимости, категорий и URL |
| `js/nm-pin.js` | Общий рисунок спрайтов пинов |
| `js/map-extras.js` | Прогресс по картам/регионам, синхронизация настроек, заметки и флажки, горячие клавиши, история посещений, сообщения об ошибках |
| `js/map-ux.js` | Дополнительные фильтры, пресеты и переходы карта ↔ база; подключается после игрового `app.js` |
| `js/map-layers.js` | Сетка координат, подписи регионов, тепловая карта; событие `bp:map` |
| `js/marker-stack.js`, `css/marker-stack.css` | Выбор среди наложенных меток |
| `js/lightbox-zoom.js` | Просмотр и увеличение изображений |
| `js/report-marker.js` | Кнопки исправлений в попапах, интеграция с очередью сообщений |
| `js/map-topbar.js`, `js/topbar.js` | Меню исходных HTML; новый каркас заменяет их в соответствующих маршрутах |

Классы `.leaflet-*` в стилях и DOM не означают, что текущий движок — Leaflet:
`BPMap` сохраняет совместимость с прежними окнами и координатами. Например,
зум MapLibre переводится из прежних единиц со сдвигом −1.

Типичный порядок: MapLibre → BPMap → вспомогательные модули → категории/карты →
NM-пины → Firebase lazy → MapExtras → MapCore → слои → игровой `app.js` → MapUX.
Точный порядок смотреть в исходном HTML конкретной игры. Общие скрипты могут
использовать глобальные переменные и функции игрового движка; не превращать их
в независимые ES-модули без проверки связей.

## 7. Прогресс и внешние сервисы

- **localStorage** — найденное, свои метки, настройки, вид карты, заметки,
  флажки, избранное и недавние карты. Ключи зависят от игры и карты.
- **Firebase Authentication + Firestore** — Google-вход и синхронизация карт;
  SDK загружает по требованию `js/firebase-lazy.js`. Документы прогресса и
  настроек находятся под `users/{uid}/mapProgress/`; очередь исправлений —
  коллекция `reports`. Конкретные ключи и слияние смотреть в `app.js` и MapCore.
  Существующий облачный документ главный (и на карте, и на главной в `js/script.js`).
  `cloudPush` (MapCore) ничего не пишет, пока `cloudPull` игры не прочитал облако
  (`cloud.synced === uid`): иначе `.set()` затёр бы облачный прогресс локальным.
  Отметки до синхронизации накладывает `mergeLocalEdits`. Импорт JSON отклоняет
  файл другой карты (поле `map`).
- **Личный кабинет** — `js/cabinet.js`, тот же Google-вход Firebase (`js/auth-lite.js`,
  `BPAuth.signIn` — всплывающее окно, PWA не уходит в браузер). Избранное, достижения,
  последние карты и история синхронизаций — в `users/{uid}/mapProgress/bp_cabinet`.
  Supabase снят 21.11.2026 (письмо со ссылкой открывалось в браузере, а не в PWA).
- **Эфир Twitch** — `js/twitch-live.js` на всех страницах (`TWITCH_LIVE_SCRIPT` из
  `web/components/shell/topbar.tsx`: главная, карты, служебные страницы, каркас базы и категорий).
  DecAPI `uptime` при открытии и раз в минуту, один запрос за раз, в скрытой вкладке пауза.
  Эфир — только если ответ похож на длительность; ошибка — «не в эфире». Включает `.is-twitch-live`
  у `#topbar` (логотип и название фиолетовые), показывает ссылку `#twitch-live` «● В ЭФИРЕ» и
  красит кнопку `#twitch-button` в подвале. Стили — `css/shell.css` (`--bx-twitch`).
  Предпросмотр: `?previewTwitch=live`.
  Подсчёт меток, сводка (`bp_prog`) и достижения (`bp_ach`) — общий модуль
  `js/progress-core.js` (`window.BPP`: список игр и ключей, `countMap`,
  `saveSummary`, `ACH`). Главная сохраняет сводку по событию `bp:progress`
  (`js/home-lib.js`), кабинет пересчитывает её сам (`BPP.refresh`) по каталогу
  `/data/progress-maps.json`, который пишет `web/scripts/assemble.mjs`. Избранное сливается трёхсторонне относительно `bp_fav_sync:<uid>`
  (снимок прошлой синхронизации), чтобы удаление не «воскресало».
  Событие `bp:fav` отправляется в `window`.
- **Ассеты GitHub Pages** — адреса берутся из `ASSETS_ROOT` игр; тайлы и
  `manifest.json`, изображения базы, местами локализованные попапы.
- **MapGenie media** — внешние изображения попапов; часть игр уже использует
  `popups/<id>.webp` в собственном репозитории ассетов. Смотреть реальный `img`
  и `popupImgUrl` игры, не заменять источники автоматически.

ID существующих меток и ключи хранения — часть совместимости с уже сохранённым
прогрессом. `progress-index.json` содержит списки ID по файлам меток: главная
считает прогресс без загрузки полных описаний. У многих игр индекс делает
игровой `build_data.py`, у Tainted Grail и Gothic — локальный
`scripts/build_progress_index.py`.

## 8. База данных

Входные данные есть для `tainted-grail`, `gothic-remake`, `skyrim`:
`data/db/<игра>/*.json`. Разделы зависят от игры: items, quests, locations,
characters, bestiary, talents, effects, lore, tips, spells и другие;
`meta.json` и `minimap.json` — служебные данные.

`scripts/db_pages.py` содержит реестр `DB`, класс `Game`, построение каталога,
страниц записей, связей с метками и мини-карт. Выход:

- `/db/index.html` — выбор базы (`hub()`: баннер `img/db-hero-art*.webp`, карточки `.dbh-*` в конце `css/db.css`);
- `/db/<игра>/index.html` и `index.json` — каталог и клиентский индекс;
- `/db/<игра>/<раздел>/<запись>/index.html` — статические записи;
- `/db/<игра>/marker-links.json` — обратные ссылки от меток к записям базы.

Хостинг: `_site/db` выкладывается вместе с основным сайтом на GitHub Pages.
Cloudflare (Worker `db-proxy`, R2, cdn-поддомены) снят 21.11.2026 — в России он
замедлен/заблокирован. Тайлы и попапы — `broskiplay.github.io/<игра>-assets/`.

## 12. Проверка и публикация

Из корня репозитория, для полной локальной сборки:

```sh
python3 scripts/category_pages.py
python3 scripts/db_pages.py
npm run build --prefix web
npm run site --prefix web
python3 -m http.server -d _site
```

Если зависимостей нет — предварительно `npm ci --prefix web`.
Сборка и генераторы записывают файлы, в том числе исходные HTML с меню и
ссылками категорий; после запуска проверять diff.
Дополнительно по задаче: `npm run typecheck --prefix web`,
`python3 scripts/spatial_lint.py`; при проверке прежнего генератора локаций —
`python3 scripts/map_pages.py` (в обычную CI-цепочку он не входит).
При проверке новых тайлов очищать кэш и service worker браузера.

`.github/workflows/pages.yml` на push в `main` или ручной запуск выполняет:
Python 3.12 + Node 22 → категории → база → npm ci → build → site → проверки
порогов и каркаса → загрузка `_site/` → деплой Pages.
Пороги (2026-11-19): база >15000 страниц, категории >500, локации >38, карт в
каркасе ≥13; дополнительно проверяются отдельные страницы, база и каркас всех
категорий. Затем `python3 scripts/check_links.py _site` (битые локальные
href/src во всех HTML) и `node --check` для `js/*.js` и `*-map/js/*.js`.
Локально `check_links.py` запускать после `npm run site`.

Публикацию делает владелец через Claude по правилам AGENTS.md. Изменения
оставлять в рабочей папке. Текст «Что нового» согласовывать до добавления
записи; для одной этой памятки пользовательских изменений сайта нет.

на `/<игра>-map/`, полное название игры текстом — `WORDMARK` в map-sidebar.ts, `.bp-wm` в map-ux.css §5б, размер по ширине через `--n`) → «Карта | База данных» (если есть `data/db/<игра>`) → поля «Карта»
(`.map-switch`, `#map-select`) и «Область» (`#region-select`, `.zone-switch`, `#zone-block`) → поиск (+ `.bp-sb-hint` —
особая возможность игры) → прогресс → действия → «Дополнительные фильтры» (`.level-filter`) → `.bp-sb-active` (чипы
ограничений; баннер источников Dimraeth) → категории → подпись источника, «О карте».
Id и разметка элементов игры не меняются, прямые потомки `.section` сохраняются (слоты склеиваются строкой).
Неизвестный элемент `.section` попадает после действий; неизвестный элемент панели — вниз. Новый тип управления —
добавить правило в `parseSidebar`. `compactSidebar()` для такой панели ничего не переставляет, только поведение:
поле без выбора скрыто (`.bp-sb-none`), пустые категории карты и группы скрыты во всех играх, счётчик группы — сумма
видимых строк, кнопки группы «скрыть/показать» (`.group-toggle`, `.bp-gt`) скрыты в map-ux.css. «Показать/скрыть все» (`map-extras.js` → `tidySidebar`)
следует фактическому состоянию строк (`.filter-item.disabled`). Поиск не сокращает список категорий ни в одной игре.
Чипы `.bp-sb-active` — кнопки с «×» (`data-act`: found/locate/level; чипов «Только: …», «Скрыто категорий», «Включены скрытые» нет, кнопки «Сбросить фильтры» нет (убрана 21.11), `dropRestriction` в map-ux.js) — снимают своё ограничение; `.locate-clear` в общей панели скрыт (его заменяет чип «Подсветка»). «＋» на телефоне (≤480 px) сворачивает панель (`setAddMode`, map-core.js). Сенсорные размеры строки (`@media (pointer: coarse)`) стоят после общих правил §5; следить за балансом скобок в map-ux.css — лишняя `}` отключала хвост стилей на десктопе.
Строка прогресса всегда пишет область подсчёта: «В подсчёте: эта карта, <исключения из скобок progress-count | все категории>».

### 17б. Панель без скачков при загрузке (20 ноября 2026)

Против CLS панель с первой отрисовки в итоговом виде: `MapDocument` (`map-shell.tsx`) ставит `<html class="bp-sb">`
при сборке; `map-sidebar.ts` выдаёт прогресс сразу как `.bp-sb-prog` с заготовками `.bp-prog-line`/`.bp-prog-note`
(`&nbsp;`, `compactSidebar` их переиспользует, пояснение не скрывает, пока счётчик пуст) и `.btn-group.bp-sb-actions`.
До `tidySidebar` (`map-ux.css`, после §5 кнопок): «Показать все», `#add-marker-btn` и `.io-row` под рядом скрыты,
место под «＋»/«⋯» занято `::after`; `#filters-container` без `.filter-item` держит `min-height: 100vh`.
Скрипты движка (`LegacyScripts`) дополнительно объявлены в `<head>` как `preload` (`fetchPriority=low`) — качаются
параллельно с Next, а не после гидратации. Новый скрипт карты попадает туда автоматически (из `p.scripts`).
